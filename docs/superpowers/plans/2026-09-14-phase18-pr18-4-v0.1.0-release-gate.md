# Phase18 PR18-4 v0.1.0 Release Gate Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make Court Legacy explicitly tag-ready as `v0.1.0` with one reproducible release decision point, release evidence, rollback instructions, and minimal additional CI noise.

**Architecture:** Keep normal PR/main CI as the fast blocking gate already proven by Phase18-1 through PR18-3. Add a tiny repository-state release check to normal CI and a manual-only `Release Gate` workflow that composes dependency audit, repository verification, smoke/long soak, and full mobile E2E without creating extra feature-branch push runs. Version metadata and a single release document provide the human-readable decision record.

**Tech Stack:** Node.js 22.16, npm, GitHub Actions, Vitest/TypeScript, Playwright, Cloudflare Workers/Wrangler, Supabase.

**Spec:** `docs/superpowers/specs/2026-09-13-phase18-release-readiness-design.md`

## Global Constraints

- Target release is exactly `v0.1.0` / package version `0.1.0`.
- Persisted game schema remains exactly v8; PR18-4 introduces no save migration.
- PR18-4 introduces no gameplay behavior and no PvP authority/privacy/idempotency changes.
- Ordinary feature-branch pushes must not start full CI; PR and `main` remain the automatic CI boundaries.
- Long soak remains release/manual-only and must not run on every pull request.
- The existing Phase18-2 long-run report is valid release evidence because PR18-3 and PR18-4 do not change production simulation/domain behavior.

`scripts/verifyReleaseEvidence.mjs` must:

```js
import { existsSync, readFileSync } from "node:fs";
import { resolve } from "node:path";

const root = process.cwd();
const readJson = (path) => JSON.parse(readFileSync(resolve(root, path), "utf8"));
const pkg = readJson("package.json");
const lock = readJson("package-lock.json");
const version = pkg.version;
const releasePath = `docs/releases/v${version}.md`;

function assert(condition, message) {
  if (!condition) throw new Error(message);
}

assert(/^\d+\.\d+\.\d+$/.test(version), `invalid package version: ${version}`);
assert(version !== "0.0.0", "release package version must not remain 0.0.0");
assert(lock.version === version, "package-lock top-level version does not match package.json");
assert(lock.packages?.[""]?.version === version, "package-lock root package version does not match package.json");
assert(existsSync(resolve(root, releasePath)), `missing release document: ${releasePath}`);

const gameStateSource = readFileSync(resolve(root, "src/domain/model/GameState.ts"), "utf8");
const schemaMatch = gameStateSource.match(/CURRENT_GAME_SCHEMA_VERSION\s*=\s*(\d+)/);
assert(schemaMatch, "could not resolve CURRENT_GAME_SCHEMA_VERSION");
const schemaVersion = Number(schemaMatch[1]);
const release = readFileSync(resolve(root, releasePath), "utf8");

for (const heading of [
  "## Release notes",
  "## Required release evidence",
  "## Environment and deployment review",
  "## Database and save-schema review",
  "## Known issues",
  "## Rollback procedure",
  "## Tagging procedure",
]) {
  assert(release.includes(heading), `release document is missing ${heading}`);
}

assert(release.includes(`Release version: \`${version}\``), "release document version marker is stale");
assert(release.includes(`Save schema: \`v${schemaVersion}\``), "release document save-schema marker is stale");
assert(release.includes("2026-09-14-phase18-pr18-2-soak-balance-results.md"), "release document must reference the Phase18 long-soak report");

for (const script of ["verify", "test:e2e", "test:e2e:critical", "soak:smoke", "soak:long"]) {
  assert(typeof pkg.scripts?.[script] === "string", `missing required script: ${script}`);
}

console.log(`[OK] release metadata v${version}, save schema v${schemaVersion}`);
```

### Task 3: Manual-only single release decision workflow

**Files:**
- Create: `.github/workflows/release-gate.yml`
- Create: `scripts/runReleaseGate.mjs`
- Modify: `package.json`

**Interfaces:**
- Consumes: `npm run release:check`, `npm run verify`, `npm run soak:smoke`, `npm run soak:long`, `npm run test:e2e`.
- Produces: `npm run release:gate` and a manually dispatched GitHub Actions `Release Gate` workflow.

- [ ] **Step 1: Add the local release-gate runner**

`scripts/runReleaseGate.mjs` runs commands sequentially with inherited stdio:

```js
import { spawnSync } from "node:child_process";

const commands = [
  ["Release metadata", "npm", ["run", "release:check"]],
  ["Repository verify", "npm", ["run", "verify"]],
  ["Fast soak", "npm", ["run", "soak:smoke"]],
];

if (process.env.COURT_LEGACY_RELEASE_LONG_SOAK === "1") {
  commands.push(["Long soak", "npm", ["run", "soak:long"]]);
}

commands.push(["Mobile E2E", "npm", ["run", "test:e2e"]]);

for (const [label, command, args] of commands) {
  console.log(`\n[release] ${label}`);
  const result = spawnSync(command, args, {
    stdio: "inherit",
    shell: process.platform === "win32",
  });
  if (result.status !== 0) process.exit(result.status ?? 1);
}
```

Add `"release:gate": "node scripts/runReleaseGate.mjs"`.

The full E2E suite already contains all `@critical` tests, so do not run `test:e2e:critical` a second time inside this gate.

- [ ] **Step 2: Add manual-only GitHub workflow**

Create `Release Gate` with only `workflow_dispatch`; do not add `pull_request` or feature-push triggers. Use one release job that:

1. checks out the selected ref;
2. sets up Node from `.node-version` with npm cache;
3. installs dependencies;
4. runs the same retrying production dependency audit policy as CI;
5. installs Chromium;
6. runs `COURT_LEGACY_RELEASE_LONG_SOAK=1 npm run release:gate`.

Set `permissions: contents: read` and a release-specific concurrency group with `cancel-in-progress: false` so a deliberate release run is not silently replaced.

Commit as `ci: add manual v0.1.0 release gate`.
