# 学校運営・カレンダー・固定ナビ設計

## 目的

スマートフォンでどの位置までスクロールしても主要5タブへ即座に移動できるようにし、現在プレースホルダーの学校タブと、反応しない右上カレンダーボタンを実用機能へ置き換える。

今回の対象は次の3点に限定する。

1. 下部タブの常時固定
2. 学校運営画面の初期実用版
3. 週間カレンダー画面

公式大会、年度更新、卒業、新入生、イベント、スカウト実行、セーブ／ロードは別仕様とする。

## 1. 下部タブの常時固定

### 動作

- `ホーム / チーム / 育成 / 試合 / 学校`をビューポート下端へ常時固定する。
- 現在の`position: sticky`を`position: fixed`へ変更する。
- 画面本文には、ナビゲーション高とセーフエリアを加味した下余白を設定し、最下部のボタンや文章が隠れないようにする。
- ボトムシート表示中はシートをナビゲーションより前面へ表示する。
- モバイル幅では左右いっぱい、520px以上ではアプリ本体と同じ最大480pxへ揃える。
- 520px以上でアプリ本体に20pxの外余白がある場合、固定ナビも画面下から20px上へ配置する。
- iPhone等の`safe-area-inset-bottom`を反映する。

### 完了条件

- 320px、360px、390px、480pxで常に5タブが見える。
- 全タブの最下部コンテンツが固定ナビに隠れない。
- ナビ切替時にページ全体のリロードを行わない。
- 横スクロールを発生させない。

## 2. 学校運営画面

### 画面構成

学校タブ内を次の3つの内部表示に分ける。

- `設備`：初期表示。資金と8設備の状態・強化を扱う。
- `記録`：学校戦績と直近試合を表示する。
- `OB`：卒業生記録を表示する。卒業生がいない場合は空状態を表示する。

内部表示はドロップダウンではなく、画面上部のセグメントボタンで切り替える。

### 学校サマリー

常時次を表示する。

- 学校名
- 学校評判の日本語表示
- 評判ポイント
- 保有資金
- 監督名
- 通算シーズン数

評判ラベルは次の対応とする。

| 内部値             | 表示       |
| ------------------ | ---------- |
| unknown            | 無名校     |
| district-contender | 地区有力校 |
| prefectural-power  | 県内強豪   |
| national-qualifier | 全国出場校 |
| national-regular   | 全国常連   |
| elite              | 全国名門   |

### 設備一覧

次の8設備をコンパクトなカードまたは行として表示する。費用の単位は既存の`School.funds`と同じゲーム内資金単位とし、円換算は行わない。

| キー              | 表示名           | 基本費用 |
| ----------------- | ---------------- | -------: |
| gym               | 体育館           |       80 |
| trainingRoom      | トレーニング設備 |       70 |
| analysisRoom      | 分析室           |       55 |
| recoveryRoom      | 回復設備         |       60 |
| dormitory         | 寮               |       90 |
| scoutingNetwork   | スカウト網       |       75 |
| alumniAssociation | OB会             |       50 |
| studyRoom         | 学習設備         |       45 |

- 設備レベルは0〜5。
- 強化費用は`基本費用 × (現在レベル + 1)`とする。
- レベル5は最大として強化ボタンを無効化する。
- 資金不足時も強化ボタンを無効化し、必要額との差を表示する。
- 強化ボタンを押すと確認ボトムシートを開く。
- 確認シートには設備名、現在レベル、強化後レベル、費用、強化後資金を表示する。
- 確定時にのみ学校資金を減算し、設備レベルを1上げる。
- 更新は不変データとして行い、他校や選手データを変更しない。

### 設備効果の扱い

現行ロジックですでに利用されている効果は、強化後すぐに反映される。

- `trainingRoom`：週間練習の成長補正。1レベルにつき8%増加、最大40%。
- `recoveryRoom`：練習時の回復量、怪我リスク軽減、週送り時の疲労回復へ反映。

その他6設備は値と強化操作をゲーム状態へ正式に反映するが、スカウト、年度更新、資金収支等の対応機能が未実装のため、今回新しい効果計算は追加しない。画面では将来機能の名称ではなく、設備の用途説明を表示する。

### 記録表示

- 学校履歴から、公式戦勝利、公式戦敗北、県大会優勝、全国出場、全国優勝を表示する。
- `GameState.history.matches`から自校の直近5試合を新しい順に表示する。
- 対戦校名、日付、セット結果、勝敗を表示する。
- 試合履歴がない場合は空状態を表示する。

### OB表示

- `GameState.history.graduates`から自校卒業生を表示する。
- 名前、卒業年、ポジション、出場、得点、ブロック、サービスエースを表示する。
- 現時点で卒業処理が未実装のため、初期状態では空状態になる。

## 3. 週間カレンダー

### 開き方

- 右上のカレンダーボタンを押すと、ページ遷移ではなく大型ボトムシートを開く。
- 閉じた際はカレンダーボタンへフォーカスを戻す。
- Esc、背景タップ、閉じるボタンで閉じられる。

### 表示内容

- 現在日付
- 学年度
- 現在の週番号
- 今週の練習状態（未実施／完了）
- 今週の練習試合状態（未実施／完了）
- `calendar.activities`に登録済みの今後の予定を日付順に最大8件
- 予定がない場合は「登録された公式予定はありません」を表示
- 現在週から4週間分の週開始日を、週間進行の目安として表示

予定種別は次の日本語ラベルで表示する。

| 内部値                 | 表示       |
| ---------------------- | ---------- |
| practice               | 練習       |
| exam                   | 定期試験   |
| camp                   | 合宿       |
| practice-match         | 練習試合   |
| qualifier              | 予選       |
| prefectural-tournament | 県大会     |
| national-tournament    | 全国大会   |
| graduation             | 卒業式     |
| intake                 | 新入生入部 |
| recovery               | 休養       |

4週間表示は公式大会日程ではなく、現在の7日単位進行を理解するためのガイドとする。

### 次週進行

- カレンダー内にもホームと同じ「次の週へ進む」操作を置く。
- 練習未完了の場合は無効化し、理由を表示する。
- 実行時は既存の`advanceOneWeek`を1回だけ呼び、ホームと同じ状態更新を行う。
- 進行後はカレンダーを閉じ、ホームを表示する。
- ホームとカレンダーで別々の進行ロジックを持たず、Appの同じコールバックを共有する。

## 4. アーキテクチャ

### 新規単位

- `src/domain/school/facilityUpgrade.ts`
  - 設備定義
  - 費用計算
  - 強化可否
  - 学校設備強化の純粋関数
- `src/features/school/SchoolScreen.tsx`
  - 学校サマリー
  - 設備／記録／OBの表示
  - 強化確認シート
- `src/features/school/school-screen.css`
- `src/features/calendar/CalendarSheet.tsx`
- `src/features/calendar/calendar-sheet.css`

### 既存変更

- `src/App.tsx`
  - `SchoolPlaceholder`を`SchoolScreen`へ置換
  - カレンダーシートの開閉状態を追加
  - 設備強化コールバックを追加
  - ホームとカレンダーで週送りコールバックを共有
- `src/app.css`
  - 下部ナビを固定化
  - 本文下余白を調整
- `src/mobile-layout.css`
  - 固定ナビ、学校画面、カレンダーシートの幅制約

### データフロー

1. 学校画面は`GameState`から自校を取得する。
2. 強化確認は状態を変更せず、費用と強化後情報を計算する。
3. 確定時に`upgradeFacility`を呼び、新しい`GameState`をAppへ返す。
4. Appが`setAppState`で状態を置き換える。
5. カレンダーは`GameState.calendar`と週間完了状態を読み取り専用で表示する。
6. 次週進行は既存のAppコールバックを呼ぶ。

設備強化は現在のメモリ上のゲーム状態へ反映する。ブラウザ再読み込み後も保持するセーブ機能は今回の対象外である。

## 5. エラー処理

- 存在しない自校IDは画面クラッシュではなく、明示的なエラー表示とする。
- 未知の設備キーはドメイン関数で例外にする。
- レベル5、資金不足、不正レベルでは強化しない。
- 強化不可の状態でコールバックが直接呼ばれても、ドメイン関数が入力状態を変更しない。
- 対戦校や卒業生の参照先が欠けている場合、その1件だけを安全に省略する。
