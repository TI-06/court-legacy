# 高校バレー青春マネジメント 全面UI刷新デザイン

## 目的

承認済みの「濃紺・白・橙を基調としたスマートフォン向けスポーツゲームUI」と、主要4校・看板選手のアニメ調キャラクターデザインを Court Legacy の実ゲーム全体へ統合する。

今回の刷新は単なる配色変更ではなく、ホーム、選手、育成、試合、イベント、学校運営を同一のゲームデザインシステムへ揃え、監督としての次の行動と選手の個性が一目で分かる状態を作る。

## 採用方針

1. 承認済みモックアップを正式なビジュアル基準とする。
2. 既存のゲーム進行、週間育成、試合、年度更新、イベント、保存データは維持する。
3. 主要4名はリポジトリ同梱の高品質WebP素材を使用する。
4. 既存のキャラクターSVGは刷新後の画面へ表示しない。画像が登録されていない選手は、学校章、背番号、氏名、能力値だけで表示する。
5. 専用画像の読み込みに失敗した場合は画像領域だけを非表示にする。SVG、代替画像、壊れた画像アイコン、汎用シルエットへのフォールバックは行わない。
6. 学校エンブレム、ナビゲーションアイコン、装飾線に使用するSVGは継続利用できる。禁止対象は既存の選手キャラクターSVGである。
7. 未実装のガチャ機能は追加しない。下部ナビは「ホーム / 選手 / 育成 / 試合 / 学校」の5項目を維持する。
8. イベントは下部タブではなく、現在のイベントエンジンから起動する全画面ストーリー演出として実装する。
9. 外部画像URLや実行時通信へ依存せず、必要な素材はリポジトリ内へ同梱する。
10. 320px幅から480px幅まで横スクロールを発生させない。

## 対象外

- ガチャ、課金、ゲーム内通貨の新設
- ゲームルール、能力計算、試合結果ロジックの変更
- Player、School、GameStateの永続化スキーマ変更
- 主要4名以外の全選手へ専用手描き素材を用意すること
- 画像未登録選手のためにキャラクターSVGや汎用シルエットを新設すること
- PC専用の別レイアウト

## デザインシステム

### 色

- 背景最深部: `#050B14`
- 基本パネル: `#0B1A2D`
- パネル強調: `#102945`
- 主アクセント: `#F47A18`
- 補助アクセント: `#2E8BD8`
- 本文: `#F4F7FB`
- 補助文字: `#A9B8CA`
- 明色カード: `#F5F6F7`
- 危険・警告: `#E34848` / `#E3A53A`

学校テーマ色は既存 `resolveSchoolVisualTheme` の値を局所アクセントとして使用し、アプリ全体の濃紺基調を崩さない。

### 形状・階層

- 大型パネル角丸: 18px
- 小型カード角丸: 12px
- タグ・ステータス角丸: 999px
- パネル境界: 明度差と1pxの半透明線で表現
- 数値、背番号、総合力は通常文字より1段階以上大きく表示
- 主要操作は44px以上のタップ領域を確保

### タイポグラフィ

- 日本語本文は既存のシステムフォント構成を維持
- 見出し、数値、英字ラベルは太字と字間でゲームUIらしい階層を作る
- 装飾目的で画像化された日本語テキストは使用しない

## アーキテクチャ

### 1. テーマ層

以下を新設する。

- `src/ui/theme/game-theme.css`
  - 色、余白、角丸、影、文字サイズ、ナビ高さをCSSカスタムプロパティで定義
- `src/ui/theme/GamePanel.tsx`
  - 明色、暗色、強調の3種類を扱う共通パネル
- `src/ui/theme/GameIcon.tsx`
  - App内に散在するアイコンパスを共通化
- `src/ui/theme/StatBar.tsx`
  - 能力、疲労、経験値、進捗で共通利用できるバー

既存画面固有CSSは一度に削除せず、共通トークンへ段階的に置き換える。

### 2. アプリシェル

`App.tsx` の責務を減らし、以下へ分割する。

- `GameHeader`
  - 現在画面名、保存状態、セーブ、カレンダーを表示
- `BottomGameNav`
  - ホーム、選手、育成、試合、学校
- `GamePageFrame`
  - セーフエリア、固定ナビ、最大幅、背景装飾を管理

現在の `AppTab` とゲーム状態管理は維持し、見た目と構造のみを移す。

### 3. キャラクター画像

#### 主要4名

- 黒羽 隼斗
- 瀬戸 蒼真
- 火神 蓮
- 白間 湊

各選手へ以下を用意する。

- 上半身立ち絵 1点
- 全身立ち絵 1点
- SDキャラクター 1点
- 表情差分 4点: 通常、真剣、喜び、悔しさ

透明背景WebPのみを使用する。PNGフォールバックは設けない。Viteが静的資産としてバンドルする。

`src/domain/appearance/featuredCharacterArt.ts` に素材マニフェストを置き、`characterId` と `variant` から画像URLを解決する。

`FeaturedPlayerArt` は次の規則で表示する。

- 登録済み素材を `<img>` で表示する
- `onError` 発生時は当該画像をDOMから非表示にする
- `PlayerCharacter`、別画像、シルエットへ切り替えない
- 氏名、学校、背番号、状態は画像と独立したテキストとして残す

#### 主要4名以外の選手

- キャラクター画像を表示しない
- 一覧では学校章、背番号、氏名、ポジション、学年、状態、能力バーを表示する
- 詳細では画像領域を生成せず、プロフィールと能力情報を全幅で表示する
- 既存 `appearanceSeed` とキャラクターSVGはゲームロジック互換のためデータ上残してよいが、刷新後の画面から参照しない

### 4. 画面コンポーネント

#### ホーム

- シーズン、日付、週番号、チームランクを1枚の上部カードへ集約
- 主要4名が自校にいる場合のみ大型ヒーロー画像を表示
- 主要4名がいない場合は学校章とチーム情報を中心にした画像なしのヒーローカードを表示
- 次戦相手、戦力比較、試合実施状況を明確化
- 育成、選手、試合、カレンダーのクイック操作
- 今週の必須行動と「次の週へ進む」を画面下部の固定実行領域へ配置
- 怪我、疲労、直近試合は小型レポートへ圧縮

#### 選手一覧

現在の `TeamScreen` を「選手」画面として再構成する。

- ポジションフィルター
- 先発、控え、登録外のセグメント
- 主要4名のみSD画像を表示
- その他の選手は画像を置かず、学校章と背番号を識別要素にする
- 学校章、背番号、氏名、ポジション、総合評価
- 攻撃、守備、跳躍、スタミナ、メンタルの要約バー
- 編成状態、怪我、疲労、主将、看板選手をバッジ表示
- カード選択で選手詳細を開く

既存の先発・リベロ・安全交代操作は一覧上部の編成モードから利用できる状態を維持する。

#### 選手詳細

`TeamScreen` 内のサブビューとして追加し、URLルーターは導入しない。

- 主要4名のみ大型立ち絵を表示
- 画像未登録選手では画像領域を生成しない
- 背番号、氏名、学校、ポジション、学年
- 総合評価と能力バー
- 疲労、士気、信頼、コンディション、怪我
- 特性・性格タグ
- 選手プロフィール
- 主要4名のみ表情ギャラリー

閉じる操作で元の一覧位置へ戻る。

#### 育成

- 今週の設定要約を暗色の戦術ボード風カードへ変更
- 練習選択、重点選手、個人指示をアイコン付きカードへ変更
- 選手選択カードは主要4名のみSD画像を表示し、その他は画像なしで表示
- 実行確認と結果は既存ボトムシートを新テーマへ統一
- 能力上昇、疲労、怪我リスクを `StatBar` と差分数値で表示

週間1回制限と既存ドメイン処理は変更しない。

#### 試合

- 対戦校エンブレム、学校名、戦力を上部スコアボードへ集約
- セットスコアと試合経過を濃紺背景へ統一
- 開始前は戦力比較と注意選手を表示
- 注意選手が主要4名の場合のみ画像を表示
- 試合後は勝敗、セット内訳、活躍選手、疲労影響を表示
- 既存の試合シミュレーション結果のみを利用し、新しい勝敗計算は追加しない

#### イベント

現在の `EventDialog` を全画面のストーリー画面へ変更する。

- 学校または体育館の背景
- 当事者が主要4名の場合のみ立ち絵を表示
- 当事者が画像未登録の場合は立ち絵領域を表示しない
- 章・カテゴリ・イベント名
- 話者名と会話本文
- 選択肢ボタン
- 結果表示

イベント解決前は閉じられない既存仕様を維持する。対象選手が存在しない場合は学校エンブレムと汎用背景を表示する。

#### 学校

- 学校章、評判、資金、監督、戦績をトップカードへ集約
- 設備、記録、OBのセグメントは維持
- 設備強化をゲームカード化し、費用と効果を同時表示
- 宿命校と因縁度を学校サマリーへ表示

### 5. 状態とデータフロー

- `App` が保持する `GameState` と `teamSelection` は現状を維持
- `selectedPlayerId: PlayerId | null` をUIローカル状態として追加
- 選手詳細は永続化しない
- イベント画面は `gameState.pendingEvent` を表示し、既存 `resolveEventChoice` へ選択IDを渡す
- キャラクター画像は Player と School から `characterId` を解決し、素材マニフェストを参照する
- 画像の読み込み失敗状態は `FeaturedPlayerArt` 内だけで保持し、GameStateへ保存しない
- 画面コンポーネントはドメイン状態を直接変更せず、既存コールバックを呼ぶ

## エラー処理

- 学校または選手参照が欠落した場合、画面全体を落とさず汎用カードを表示する
- 専用キャラクター画像が登録されていない場合、画像要素を生成しない
- 専用キャラクター画像が読み込めない場合、当該画像要素を非表示にする
- キャラクターSVG、別画像、汎用シルエットへのフォールバックは禁止する
- イベント背景が未定義の場合、カテゴリ別のCSS背景を表示する
- 保存失敗、読込失敗、未来バージョン拒否は既存メッセージを新しい通知UIへ表示する
- 操作不能な状態ではボタンを無効化し、理由を近接テキストで示す

## アクセシビリティ

- キャラクター画像は装飾扱いとし、氏名、学校、状態はテキストでも表示
- 選択中タブには `aria-current="page"`
- ダイアログと全画面イベントはフォーカストラップを維持
- 重要な保存状態と結果は `aria-live` で通知
- 色だけで状態を区別せず、アイコン、文言、バッジを併用
- `prefers-reduced-motion` と既存 `reducedMotion` 設定を尊重
- 画像非表示時にも操作名と選手情報が欠落しない

## レスポンシブ方針

- 320px: 1カラム、文字省略を最小化、カード余白を圧縮
- 360pxから430px: 基準レイアウト
- 480px: 余白とキャラクター表示を拡大
- 520px以上: 最大幅480pxのスマートフォンフレームとして中央配置
- 横スクロールは禁止
- 下部ナビと固定実行領域はセーフエリアを加味する
- 画像が存在しないカードでは情報領域を全幅へ拡張する

## アニメーション

- 画面切替: 120〜180msのフェードと短い移動
- 能力バー: 初回表示時のみ伸長
- ボタン: 押下時の縮小を最大2%
- イベント立ち絵: 低速フェードイン
- `reducedMotion` 時は即時表示へ切り替える
- 画像読み込み失敗時に切替アニメーションは行わない

## テスト

### 単体・コンポーネント

1. `GameHeader` と `BottomGameNav` が現在タブを正しく表示する。
2. `StatBar` が範囲外値を0〜100%へ丸める。
3. 主要4名の専用素材定義が解決される。
4. 画像未登録選手ではキャラクター画像要素を生成しない。
5. 専用素材の `error` 発生時に画像が非表示となり、`PlayerCharacter` が生成されない。
6. 選手一覧のフィルターと編成表示が正しく動作する。
7. 選手カードから詳細を開き、一覧へ戻れる。
8. イベント選択肢が既存 `resolveEventChoice` へ正しいIDを渡す。
9. 既存の育成、試合、設備、セーブ機能のテストを維持する。

### E2E

1. 320px、360px、390px、430px、480pxで全5タブに横スクロールがない。
2. ホームから育成を実行し、次週へ進める。
3. 選手一覧から主要4名と画像未登録選手の詳細を開ける。
4. 主要4名の画像が一覧、詳細、ホーム、イベントで表示される。
5. 画像未登録選手のカードにキャラクターSVGが表示されない。
6. 画像読み込みを失敗させても壊れた画像アイコンと代替キャラクターが表示されない。
7. 練習試合を開始し、結果からホームへ戻れる。
8. 強制イベントで背景、選択肢が表示され、解決できる。
9. セーブ、再読込後もゲーム状態が維持される。
10. `reducedMotion` 設定で主要アニメーションが無効になる。

## 実装分割

### Phase 1: デザイン基盤とアプリシェル

テーマトークン、共通パネル、共通アイコン、能力バー、ヘッダー、下部ナビを実装する。

### Phase 2: キャラクター画像基盤

主要4名のWebP素材、素材マニフェスト、`FeaturedPlayerArt` を実装する。既存キャラクターSVGへの参照を刷新対象画面から除去する。

### Phase 3: ホームと選手

ホーム、選手一覧、選手詳細を刷新する。主要4名は画像を表示し、その他の選手は画像なしで成立するレイアウトにする。

### Phase 4: イベント

`EventDialog` を全画面ストーリー表示へ変更し、背景、登録済み立ち絵、選択肢を統合する。

### Phase 5: 育成・試合・学校

残りの既存画面とボトムシートを同じデザインシステムへ統一する。選手画像の表示規則は全画面で統一する。

### Phase 6: 旧キャラクターSVG参照の除去と総合検証

刷新後画面から `PlayerCharacter` と関連CSSの参照を除去し、未参照になった場合はコンポーネントと専用テストを削除する。全単体テスト、モバイルE2E、ビルド、アクセシビリティ、横スクロール、保存互換を確認する。
