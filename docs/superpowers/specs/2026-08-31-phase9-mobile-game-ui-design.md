# Phase 9 Mobile Game UI Redesign

## Goal

Court Legacy の既存機能は維持したまま、UI を「スマホで縦に情報を読むWebアプリ」から「スマホゲームの管理画面」へ寄せる。

最優先は次の3点。

1. ホーム画面で、今週の状況と次に押す操作を初期表示内で把握できること。
2. 大会画面で、自校の現在地・対戦相手・勝敗を一目で把握できること。
3. 文字を小さくして詰め込むのではなく、可読性を保ったままカード構成と情報重複を削って情報密度を上げること。

今回のUI方針は「A: ゲーム管理画面型」。本文は14pxを基準にし、カードはコンパクトにする。

---

## Scope

### In scope

- 共通タイポグラフィ
- 共通余白、角丸、タップ領域
- 下部ナビゲーションの高さと文字サイズ
- ホーム画面の情報構造再編
- 大会画面の情報構造再編
- 320 / 360 / 390 / 414 / 480px のモバイルレイアウト監査
- 既存 E2E のUI変更追従

### Out of scope

- ゲームバランス変更
- 大会ロジック変更
- 練習・試合のドメインルール変更
- 選手、育成、ショップ、PvP の全面再設計
- PC向け専用レイアウト

ただし、Phase9で定義する共通UIトークンは後続画面へ展開できる構造にする。

---

## Design principles

### 1. 1画面目に判断材料を置く

ユーザーが画面を開いた直後に「現在どうなっているか」「次に何をすればいいか」が分かることを優先する。

### 2. 説明文より状態を見せる

操作方法の長文説明はホームから削る。必要な説明は遷移先や補助UIに寄せる。

### 3. 重複表示を減らす

同じ情報を別カードで2回見せない。特にホームの疲労・怪我、公式戦情報、大会画面の次戦情報を整理する。

### 4. 小さい文字で密度を稼がない

12px未満の文字は使用しない。本文14pxを基準とし、情報密度はレイアウト圧縮で確保する。

### 5. スクロールは詳細確認のために使う

主要操作に到達するための長いスクロールは避ける。

## Shared UI tokens

### Typography

| Usage | Size | Weight | Line height |
| --- | ---: | ---: | ---: |
| Screen title | 22px | 800-900 | 1.2 |
| Card title | 18px | 800 | 1.25 |
| Section heading | 16px | 800 | 1.3 |
| Body | 14px | 500-600 | 1.45 |
| Button | 14-15px | 800 | 1.2 |
| Label | 12px | 700 | 1.3 |
| Caption | 12px | 500-600 | 1.4 |
| Bottom navigation | 12px | 700 | 1.2 |
| Important metric | 20-24px | 800-900 | 1.0 |

Rules:

- 12px未満は使用しない。
- 通常本文は14pxを基本とする。
- 320px幅でも文字サイズを下げて解決しない。必要ならレイアウトを組み替える。

### Spacing

| Token | Value |
| --- | ---: |
| xs | 4px |
| sm | 8px |
| md | 12px |
| lg | 16px |

カード間は8〜12pxを基本とし、既存の14〜16px連続配置を削減する。

### Radius

| Token | Value |
| --- | ---: |
| small | 10px |
| card | 14px |
| large | 18px |

### Touch target

| UI | Minimum |
| --- | ---: |
| Icon / normal control | 44px |
| Primary action | 48px |
| Round tab | 44px |

見た目の高さが小さくても、タップ可能領域は44px未満にしない。

# Home screen redesign

## Current issue

現行 HomeScreen は次の7ブロックを縦積みしている。

1. 監督ホーム / 練習試合候補
2. チーム指標4枚
3. 公式戦
4. 今週の行動3枚
5. 週送り
6. 直近の試合
7. 監督レポート

その結果、「次の週へ進む」までの距離が長く、疲労・怪我など一部情報も重複している。

## New structure

7ブロックを以下の4ゾーンへ再編する。

1. Compact header
2. This week card
3. Team status strip
4. Official match + recent status

### 1. Compact header

表示内容:

- 学校名
- 保存状態
- 日程ボタン
- 日付
- 就任年数
- 週番号

「監督ホーム」という大見出しは削除する。現在地は下部ナビで判断できるため、専用タイトル行を持たない。

目標高さ: 58〜64px。

例:

```text
青葉高校        保存済 ✓   [日程]
4/22・就任1年目・17週目
```

### 2. This week card

ホームの主役とする。

このカードへ以下を統合する。

- 今週の練習試合候補 / 対戦相手
- 自校戦力
- 練習設定状態
- 練習試合状態
- 育成への導線
- 編成への導線
- 試合への導線
- 次の週へ進む

例:

```text
今週                       4/22
練習試合  光ヶ丘高校       戦力48

練習  設定済 ✓       試合  未実施

[ 育成 ] [ 編成 ] [ 試合 ]

      [ 次の週へ進む ]
```

カード全体は180〜210pxを目標とする。

ホームでは以下のような長文説明を常時表示しない。

- 申し込み・受諾で今週の対戦相手を決めます。
- 設定した練習は週送り時に実施。
- 疲労・状態・怪我の残り週数を更新して次週へ進みます。

必要な補助情報は、状態ラベルまたは遷移先で表示する。

### 3. Team status strip

現行の独立した4カードを廃止し、1枚のパネル内で4指標を横並びにする。

390px以上:

```text
評判       疲労       部員       結束
20         14         12         52
無名校     安定       怪我1      横ばい
```

- ラベル: 12px
- 数値: 20px / 900
- 補足: 12px
- 高さ: 68〜76px目安

320pxでは2x2への切替を許可する。

### 4. Official match + recent status

公式戦は通常時に80〜100px程度のコンパクトカードとする。

例:

```text
公式戦                         あと5週
インターハイ県大会
1回戦   vs 城南商業           [大会表 ›]
```

公式戦が今週ならCTAを強くする。

```text
公式戦                         今週
インターハイ県大会
準々決勝  vs 城南商業

        [ 公式戦へ ]
```

直近結果と監督レポートは重複を削る。

例:

```text
最近  ○ 城東高校に 2-0 勝利
注意  △ 怪我1人
```

問題がない場合は注意行自体を表示しない。

## Home viewport acceptance

390x844 を主要基準とする。

初期表示内に最低限以下が見えること。

- 学校名 / 日付 / 保存状態
- 今週の対戦情報
- 育成 / 編成 / 試合導線
- 次の週へ進む
- チーム主要4指標
- 次の公式戦の要約
- 下部ナビ

360x800でも「次の週へ進む」は初期表示内に置く。

320pxではステータスの2x2化を許可するが、横スクロールは禁止する。

# Tournament screen redesign

## Current issue

現行大会画面は、大会概要のheroと下部の「次の試合」アクションカードで同じ次戦情報を重複表示している。

また、ラウンド切替は導入済みだが、対戦カードが縦2段構成で、スマホ横幅を活用できていない。

## Primary model

大会画面は「ラウンド別一覧」を主役とする。

全体トーナメント図はPhase9必須にはしない。必要なら将来「全体表」補助表示として追加する。

## New structure

1. Compact tournament header
2. Current position strip
3. Round segmented tabs
4. Single-line match rows
5. Inline official match CTA

### 1. Compact tournament header

現行の「試合メニューへ戻る」という独立テキスト行をやめる。

```text
← インターハイ県大会       あと8週
   県大会・16校
```

- 戻る操作: 44pxタップ領域
- 大会名: 18px / 800
- 状態: 12px / 800
- 補足: 12px

### 2. Current position strip

```text
現在  1回戦       次戦  城南商業
```

- ラベル: 12px
- 値: 14px / 800

大会名と次戦情報を繰り返さない。

### 3. Round segmented tabs

```text
[ 1回戦 ][ 準々決勝 ][ 準決勝 ][ 決勝 ]
```

- 最低高さ: 44px
- 文字: 12px / 800
- 選択中: 背景 + 明確なアンダーラインまたはアクセント
- 完了済: 必要に応じてチェック状態を付与可能
- 360px以下でも文字サイズは12pxを維持する

### 4. Single-line match rows

1試合を1行で表示する。

終了済:

```text
桜台高校        2 - 1        白峰高校
```

未実施:

```text
瑞穂高校         VS          皇星高校
```

自校:

```text
青葉高校        2 - 0        城南商業
```

「自校」「★自校」などの専用行や専用ラベルは表示しない。

自校は以下のみで識別する。

- 自校名を800〜900 weight
- 自校名をアクセント色
- 行背景をごく薄いアクセント色
- 必要なら2〜3pxの左アクセントライン

自校が片側にある場合、該当校側だけを強調し、相手校まで同じ強調色にしない。

#### Match row typography

- 学校名: 14px / 700
- 自校名: 14px / 800〜900
- スコア: 18〜20px / 900
- VS: 12〜13px / 700
- 状態: 12px / 800
- 行高さ: 48〜56px目安

学校名は `shortName` を基本表示に利用する。320pxで幅が不足する場合も折り返さず、省略記号で1行を維持する。フル校名はアクセシブルネームまたは詳細画面で確認できるようにする。

#### Alignment

3カラムで固定する。

- 左校: 左寄せ
- スコア / VS: 中央固定
- 右校: 右寄せ

スコア列の幅を固定し、学校名の長さでスコア位置が揺れないようにする。

### 5. Self match ordering

選択ラウンドに自校の試合がある場合、表示上は自校の試合を先頭へ出す。

その後に「他の試合」を表示する。

本来の大会データ配列や勝ち上がりロジックは変更しない。これはプレゼンテーション上の並べ替えのみとする。

### 6. Inline official match CTA

今週の自校公式戦がある場合、別の「次の試合」カードを下部に追加しない。

自校行の直下へCTAを統合する。

例:

```text
青葉高校          VS          城南商業   今週

          [ 公式戦を開始 ]
```

自校行部分は1行を維持し、CTAが必要なときだけ行の下に追加する。

練習条件で開始不可の場合は、ドメイン条件に合わせた短い状態表示とする。Phase8の練習実行タイミングと矛盾する文言を残さない。

### 7. Tournament terminal state

敗退:

```text
インターハイ県大会           終了
準々決勝敗退
```

優勝:

```text
🏆 インターハイ県大会
県大会 優勝
```

敗退時は過度に大きい終了カードを置かない。優勝時のみ演出を少し強める。

## Tournament viewport acceptance

390x844 で以下がスクロール前に見えること。

- 大会名
- 現在ラウンド
- 次戦
- 4ラウンドタブ
- 自校試合
- 他校試合を複数行
- 下部ナビ

1回戦8試合は縦スクロールを許可するが、上部概要のために試合一覧が大きく押し下げられないこと。

横スクロールは禁止する。

---

# Bottom navigation

現行約70pxから、60〜64px程度へ圧縮する。

- アイコンは認識性を維持
- ラベルは12px
- 各タップ領域は44px以上
- safe-area-inset-bottom は維持
- 320pxでも文字サイズを下げない

---

# Responsive rules

## 320px

- ステータスは2x2化可能
- 大会対戦行は `shortName` + 省略表示を使用
- 文字サイズは維持
- 横スクロール禁止

## 360px

- 最小標準レイアウト
- ホームの「次の週へ進む」は初期表示内
- 大会タブは4分割のまま維持

## 390px

- 主要設計基準
- ホーム主要情報を初期表示内へ集約
- 大会の自校行と複数の他校行を初期表示

## 414px

- 390pxの構造を維持
- 余剰幅は文字拡大ではなく、左右余白と学校名表示幅へ利用

## 480px

- UIを巨大化しない
- 390〜414pxと同じ情報密度を維持
- コンテンツ幅を広げすぎず、中央密度を保つ

---

# Accessibility / interaction

- `aria-pressed` をラウンドタブで維持する。
- disabled操作は色だけでなく状態属性でも表現する。
- 自校の識別を色だけに依存しない。太字または背景差も併用する。
- focus-visible は既存仕様を維持する。
- ローディング中は処理中テキストまたは状態表示を必ず出し、無反応に見せない。

## E2E update

既存のmobile layout auditをPhase9基準へ更新する。

最低対象幅:

- 320
- 360
- 390
- 414
- 480

### Home assertions

- `scrollWidth <= viewportWidth`
- 下部ナビが主要操作を覆わない
- 360x800で「次の週へ進む」が初期ビューポート内
- 390x844で公式戦要約が初期ビューポート内
- 実効font-sizeが12px未満の可読テキストがない

### Tournament assertions

- 横スクロールなし
- ラウンドタブ4個が1行表示
- 対戦は `左校 / score-or-VS / 右校` の1行構造
- 自校専用ラベル行を作らない
- 自校試合が選択ラウンド内の先頭に表示される
- 390x844で自校試合が初期ビューポート内
- 今週の自校公式戦ではCTAが自校試合と同じブロックに存在する

# Non-goals / guardrails

- UI改善のためにゲーム進行ロジックを変更しない。
- 画面を1ページに収めるために12px未満の文字へ戻さない。
- 320pxだけを理由にラウンドタブを横スクロール化しない。
- 大会表を再び横スクロール式トーナメントへ戻さない。
- ホームに説明文を大量復活させない。
- 既存の処理状態表示を削除しない。

---

# Definition of done

Phase9 UI redesign is complete when:

1. 共通文字サイズとタップ領域が上記基準へ整理されている。
2. ホームで主要操作と主要状態が初期表示内に収まる。
3. 「次の週へ進む」まで長いスクロールが不要になる。
4. 大会の対戦表示が横1行 `A 2-0 B` / `A VS B` 形式になる。
5. 自校専用行を使わず、文字・太さ・背景差で自校を認識できる。
6. 大会上部の重複情報が削除され、自校試合が見つけやすい。
7. 320 / 360 / 390 / 414 / 480px で横スクロールがない。
8. quality と mobile E2E がすべてGREENになる。
